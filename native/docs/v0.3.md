# Vora 0.3 validation and repair

Vora 0.3 adds deterministic output contracts to the native C++ runtime. The
engine checks returned text after inference and before making its result
available to dependent steps.

## Syntax

```text
require STEP sentences NUMBER
require STEP contains "EXACT TEXT"
forbid STEP contains "EXACT TEXT"
repair STEP max NUMBER
```

Sentence counts range from 1 to 100. Repair limits range from 1 to 5. A repair
directive requires at least one validation rule on the same step. Rules may
refer to a step declared later, consistent with Vora's forward-reference
support.

## Runtime behavior

All rules on the completed step are evaluated together. If they pass, the step
completes normally. If they fail and a repair remains, the runtime emits a
`step_repair` event containing the step, provider-attempt number, repair number,
repair limit, and number of failed checks. Prompt or output content is not
written to the event trace.

The next provider call receives the original prompt and concrete failed
constraints. A repair is a new model call and consumes the atomic shared call
limit. It does not consume the transient network retry allowance. Provider
construction occurs once per step, so state is retained across both kinds of
attempt.

If no repair is declared, or all repairs fail, the engine emits
`validation_failed`, stops dependent work, and returns a sanitized execution
error. Existing workflows without the new directives preserve their behavior.

## Boundaries

Exact-text matching is case-sensitive. Sentence counting treats each run of
`.`, `!`, or `?` as one terminal marker. These intentionally small validators
are reproducible and useful for explicit format constraints. They do not judge
meaning, truth, tone, arithmetic, prompt injection, or semantic equivalence.

## Verification

Native parser tests cover valid rules, plan serialization, forward declarations,
invalid ranges, duplicate repairs, missing validations, and empty strings.
Runtime tests cover successful repair, simultaneous failures, trace metadata,
call accounting, exhausted repairs, and punctuation-run counting. The existing
critique-schema, concurrency, retry, HTTP contract, and failure-redaction tests
remain enabled.
